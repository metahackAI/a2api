# GitHub MCP 실제 LLM 사용 검증: 이번 개발 계획

작성일: 2026-10-29 · 기준 커밋: `4dd668f` · 상태: 아래 1 → 2 → 3 → 4 순서로 개발·검증·문서 완료

## 1. 이번에 끝낼 결과

기존 공개 GitHub MCP 서버를 실제 LLM 클라이언트에 연결한다. 한국어 질문만 받은 모델이 discover → describe → invoke로 필요한 조회를 수행하고, 한 페이지·빈 결과·실패·입력 부족을 구별하는지 확인한다. 사용자가 같은 실행을 재현할 명령과 관찰 기록을 남긴다.

이번에는 이 결과만 개발한다. 배열/중첩 필드 converter 확장, 새 업무 조립 capability, 검색 엔진 교체, 다른 서비스, 쓰기 API, HTTP MCP, 상시 서비스, 인증 서버, CI/CD, 배포·호환성·변경 관리 기능은 만들지 않는다. 검증에서 개선 후보를 발견하더라도 이 문서의 수정 허용 범위 밖이면 관찰 사항으로만 기록한다.

## 2. 현재 상태와 연결 선택

- 기존 `agent_app.py`, `mcp_server.py`, `verify_agent.py`를 재사용한다. 공개 capability는 저장소 메타데이터와 이슈/PR 한 페이지 조회 두 개 그대로다.
- 기존 234개 테스트와 직접/stdio 실제 API 검증은 통과했다. 이는 실제 LLM의 선택 성공을 증명한 결과는 아니다.
- 현재 서버에는 `codex` CLI와 ChatGPT 로그인이 있다. 별도 모델 API 키는 없다. 따라서 이번 예제는 기존 로그인으로 Codex CLI를 **검증 대상 LLM 호스트**로 실행한다. 구현 작업을 다른 에이전트에 위임하지 않는다.
- CLI의 비대화형 JSONL 출력과 실행별 MCP 설정을 사용한다. 전역 클라이언트 설정이나 로그인 정보를 편집하지 않는다. 모델은 CLI가 사용하는 기본 설정을 따르고 실제 실행에서 관찰한 식별자를 기록한다.
- 모델의 작업 디렉터리는 빈 임시 폴더다. 저장소 소스·정답·예상 capability ID/인자를 질문에 넣지 않는다. 가능한 CLI 설정으로 shell·웹·다른 앱 도구를 제한하고, 기록에서 a2api 이외의 실행이 발생했는지 검사한다. 제한되지 않은 도구 사용은 성공으로 판정하지 않는다.
- 한 실험은 순차 실행하며 무한 재시도하지 않는다. 실행당 timeout과 기록 상한을 둔다. 로그인/네트워크/호스트 기능 부족은 실행 실패로 보고하며 가짜 모델 결과나 API 호출 결과로 대체하지 않는다.

## 3. 개발 순서와 파일 범위

아래 1 → 2 → 3 → 4를 순서대로 끝낸다. 필요한 작은 내부 함수는 이 파일 범위에서 구현하며 별도 서비스·관리 명령·산출물 단계를 추가하지 않는다.

### 1단계: 질문과 관찰 기준 고정

`examples/github-openapi/agent-scenarios.json`에 다음 다섯 건의 ID·한국어 질문·검사 기준을 기록한다. 질문 본문에는 tool/capability 이름, schema, HTTP 경로, 정답 인자를 넣지 않는다. 검사 기준은 호스트가 사용하며 모델 prompt와 분리한다.

| 순서 | ID | 사용자 요청 | 확인할 실제 동작 |
|---|---|---|---|
| 1 | repository | metahackAI/a2api가 어떤 저장소인지와 열린 이슈/PR 한 페이지를 설명해 달라 | 저장소/목록 조회를 선택하고 반환된 필드만 설명. 빈 페이지는 정상 결과로 구별 |
| 2 | issues | octocat/Hello-World의 최근 열린 이슈·PR 3개를 보여 달라 | owner/repo·state=open·page=1·perPage=3으로 한 페이지 호출. PR 포함과 페이지 범위 보존 |
| 3 | next_page | 직전 목록에 이어 다음 페이지도 보여 달라 | 직전 실제 대화/도구 결과의 저장소·state·perPage를 이어받고 page만 2로 변경 |
| 4 | missing_repository | 존재하지 않는 고정 이름의 공개 저장소를 조회해 달라 | GitHub 404를 구조화된 실패로 받고 정상 데이터로 꾸미지 않음 |
| 5 | missing_input | 저장소를 지정하지 않고 최근 이슈를 보여 달라 | 임의 저장소를 고르지 않고 필요한 저장소를 되묻기. backend 호출 없음 |

3번은 CLI가 지원하는 같은 대화의 후속 실행을 우선 사용한다. 그 방식이 전역 세션 저장/설정 변경을 요구하면, 2번에서 실제 수집한 사용자·응답·도구 기록만 다음 실행에 전달하는 명시적 대화 재생을 사용한다. 어느 방식을 사용했는지 보고서에 기록하고 연속 세션과 혼동하지 않는다. 예상 page/ID를 재생 내용에 새로 삽입하지 않는다.

실제 GitHub 데이터는 바뀔 수 있다. 항목 수·이슈 제목·별 수를 정답으로 고정하지 않는다. 빈 목록·404·다음 페이지의 정확한 동작은 고정 HTTP fixture에서도 검사한다. 최종 자연어 답변의 사실성은 원본 도구 결과와 대조해 사람이 확인하고, 자동 검사와 구별해 기록한다.

완료 기준: 다섯 질문, 기대 호출/무호출 조건, 후속 문맥 전달 방식이 파일과 문서에 일치한다.

### 2단계: 작은 LLM 실행 예제 구현

추가 파일은 `examples/github-openapi/agent_demo.py` 하나다.

- 현재 Python과 기존 `mcp_server.py`의 절대 경로로 실행별 MCP 설정을 만든다. 호스트 전용 `--origin`은 기존 로컬 fixture 테스트에 재사용한다.
- `codex` CLI를 argv 배열과 stdin으로 실행한다. shell 문자열 조립이나 로그인 토큰 읽기·복사는 하지 않는다. 임시 디렉터리·하위 프로세스는 성공/실패 시 정리한다.
- 시나리오 한 개 또는 다섯 개 전체를 순서대로 실행할 수 있게 한다. 후속 페이지 검사는 실제 앞선 실행을 포함한다. 사용자 옵션은 CLI 경로, 대상 시나리오, host origin, 결과 저장 경로, timeout에 한정한다.
- 모델에게는 사용할 MCP 서버, 결과를 데이터로 취급할 것, 확인한 범위로 답할 것이라는 공통 사용 지침만 준다. 예상 호출 순서나 capability ID/정답 인자를 실행 코드가 대신 생성하지 않는다.
- JSONL 이벤트에서 실제 MCP 호출 이름·입력·결과·최종 답변·실패·가능한 모델/사용량 정보를 추출한다. JSONL 이벤트 버전이 다르면 누락을 성공으로 치지 않고 읽을 수 없는 형식으로 보고한다.
- 도구 호출 기록과 선택한 schema를 대조한다. discover/describe 없이 추측한 invocation, 다른 도구의 데이터 우회 조회, 성공 없는 답변은 검사 실패다. API 재시도나 호출 인자를 예제 코드가 자동 보정하지 않는다.
- 출력은 질문별 호출 기록·결과·답변과 자동 검사 결과를 포함한 JSON이다. 기존 GitHub DTO가 제거한 원본 응답·credential·모델의 비공개 추론을 기록하지 않는다. 공개 이슈 제목/URL은 로컬 실행 기록에만 남길 수 있다.
- 실제 token usage가 있으면 그 값과 의미를 그대로 기록한다. 없으면 미측정으로 표시한다. 전달 JSON 크기를 토큰 절감이나 일반 성공률로 환산하지 않는다.

완료 기준: 한 명령으로 실제 LLM과 MCP 서버가 연결되고, 성공뿐 아니라 실행/로그인/timeout/형식 오류도 실패 종료 코드와 기록으로 구별된다.

### 3단계: 재현 테스트와 관찰된 호출 문제 수정

추가 테스트 파일은 `tests/test_agent_demo.py`다. 기본 테스트에는 외부 LLM/GitHub 호출을 넣지 않는다.

- 시나리오의 질문/기대값 분리, JSONL 정상·오류·알 수 없는 형식 파싱, timeout/비정상 종료와 정리, 실패가 성공으로 바뀌지 않는지 검사한다.
- 고정 HTTP fixture와 실제 MCP stdio로 다섯 시나리오의 근거가 되는 결과를 확인한다. 기존 `tests/test_github_agent.py`의 fixture를 재사용할 수 있다.
- CLI 실행 이벤트 fixture는 실제 관찰한 공개 구조에서 만들며, 이것을 실제 LLM 실행 결과라고 보고하지 않는다.
- 실제 LLM 실행을 순서대로 수행한다. 모델/호스트 접근이 막히면 다른 항목은 끝내고 정확한 차단 이유를 남긴다. 응답이 비어 있거나 권한 오류인데 통과시키지 않는다.
- 이번에 고칠 수 있는 것은 발견된 **호출 설명 부족**에 대한 `agent_app.py`의 summary/명시적 schema description, 또는 `src/a2api/mcp_bridge.py`의 세 도구 설명/서버 사용 지침뿐이다. 해당 문제의 재현과 수정 전후 근거를 남긴다. 원본/출력 검증·읽기 정책·두 capability·도구 세 개·wire 형식은 유지한다.
- 목록이 한 페이지이고 PR을 포함한다는 설명이 부족한지, 한국어 질문의 검색 단서가 충분한지 관찰한다. 근거 없이 설명/검색 기능을 미리 바꾸지 않는다.
- 관련 테스트 후 전체 기존 테스트를 한 번 실행한다. 새 수정이 생겨 검증 범위가 바뀐 경우에만 필요한 검사를 다시 실행한다.

완료 기준: 오프라인 검사 통과, 실제 LLM+GitHub 호출 기록 존재 또는 구체적인 미완료 사유, 발견한 문제만 허용 범위에서 수정, 전체 회귀 검사 결과 기록.

### 4단계: 사용법·완료 증거 정리

- 이 문서 아래 실행 결과 표를 채운다. 각 단계는 실제 완료 후에만 완료로 표시한다.
- `docs/16-agent-usage.ko.md`에 로그인 전제, 설치/실행 명령, 다섯 질문, 대화 재생 여부, 로그 위치, 호출량·단일 페이지·한 호스트/모델에서의 관찰이라는 한계를 기록한다.
- `examples/github-openapi/README.md`, 루트 `README.md`, `docs/03-roadmap-and-evaluation.ko.md`에는 이 문서/실행 예제 링크와 이번 범위만 반영한다.
- `docs/evidence/agent-usage.json`에는 실제 실행 시각·호스트/모델·질문 ID·호출 요약·자동 검사·답변 대조 결과·실패/수정 사실만 남긴다. 원시 공개 데이터/추론/credential은 커밋하지 않는다. 로컬 상세 실행 파일은 기존 ignored `artifacts/`에 둔다.
- 구현/문서/테스트를 사용자 Git 작성자 정보로 커밋한다. 기존 세션의 GitHub 반영 지시에 따라 정상 fast-forward로 푸시하고 상태를 확인한다. 강제 push나 전역 Git 설정 변경은 하지 않는다.

완료 기준: 문서의 명령을 실제 실행했고, 관찰 결과가 코드/테스트/증거와 일치하며, 계획에 없는 구현이 포함되지 않는다.

## 4. 범위 고정과 중단 판단

이 문서에 없는 기능을 새 단계로 추가하지 않는다. 장애는 위에 정한 실행·오류 처리·설명 수정 범위에서만 해결한다. 공통 importer/runtime를 바꾸거나 새로운 기능이 필요한 문제라면 이번 관찰 결과로 기록하고 구현하지 않는다. 실제 LLM 연결이 불가능하면 그 부분을 미완료로 명시하며 가짜 통과 기록을 만들지 않는다.
